# Project audit: what makes the image 6 GB, and what can live outside it

Audited 2026-10-07 at `200f481`, clean working tree.

## Scope

Measured inside a running box built from this Dockerfile
(`ubuntu_refresh=2026-W41`, Playwright 1.62.1, Cypress 14.5.4, Chrome
154.0.8037.97, whisper `small`, claude-code 2.1.292, codex 0.160.1):
`du -x` over the image's own filesystem (bind mounts excluded), `dpkg-query`
installed sizes, the largest files under the npm, pip and browser folders.
Read the Dockerfile, `bin/run`, `bin/build`, the README's "One of each", and
the two earlier notes, [idmap-2026-09-04](idmap-2026-09-04.md) and
[audit-2026-09-06](audit-2026-09-06.md). Tested podman's `:O` volume mount
(read-only lower folder, throwaway writes) with the nested podman in the box.

Not done: nothing measured on the host. The host's store, its dangling
images and the time of the id-mapped copy were not visible from the box; the
`:O` test ran on fuse-overlayfs, not the host's native overlay. Sizes are
allocated MiB on disk, not compressed layer sizes.

## Verdict

| | |
|---|---|
| Image on disk | 6,123 MiB |
| Of which browsers, model, CLIs | 3,497 MiB (57%) |
| Image without them | ~2.6 GB |
| Waste with no loss (duplicates, caches) | none worth a change |
| Cost of one build on the host | the image plus its id-mapped copy, ~12 GB, once a day |

Nothing in the image is a duplicate any more: September's work removed the
second Chrome, the second Chromium and rembg. What is left is 3.5 GB of
browsers, a speech model and the two agent CLIs, which all have one thing in
common: they are folders of files that no apt package depends on, keyed by a
version. That is exactly what a mounted folder can hold.

## Finding register

| Id | Severity | Area | Title |
|---|---|---|---|
| BOX-01 | high | size | Browsers, model and CLIs are baked in, and copied again by every build |
| BOX-02 | high | disk | Each daily build leaves the previous image and its 6 GB copy behind |
| BOX-03 | medium | size | Chrome and Playwright's Chromium are two Chromiums |
| BOX-04 | low | size | The rest of the image is a floor, not waste |

### BOX-01 Browsers, model and CLIs are baked in, and copied again by every build (high)

`Dockerfile:211` (Playwright), `:214` (Cypress), `:259` (whisper), `:413`
(Chrome), `:467` (headless shell), `:485` and `:493` (the CLIs).

These 3.5 GB are stored in the image's layers, and then once more: `bin/run`'s
`--userns=keep-id` makes podman copy the **whole** image for every new image
id (`bin/run:386`, warmed at `bin/build:83`; [idmap-2026-09-04](idmap-2026-09-04.md)). The CLI layers
change every day, so the 3.5 GB are rewritten every day, though Playwright,
Cypress and the model change a few times a year.

**The proposal, your idea: one folder, mounted.** `data/extras/` in the
ai-box clone, mounted by `bin/run` at `/opt/extras`:

```
data/extras/
  ms-playwright/     chromium-1234, firefox-1538, webkit-2336, headless shell
  cypress/           14.5.4
  huggingface/       faster-whisper-small
  chrome/            154.0.8037.97/, current -> 154.0.8037.97
  npm/               claude-code, codex
```

The image keeps only the environment that points there, which it has
already: `PLAYWRIGHT_BROWSERS_PATH`, `CYPRESS_CACHE_FOLDER`, `HF_HOME`,
`PUPPETEER_EXECUTABLE_PATH`, plus `/opt/extras/npm/bin` on `PATH`. Tools that
look there do not know the difference.

- **Updated only when needed.** A Playwright browser revision belongs to one
  Playwright release, a Cypress binary to one Cypress release, the model to
  its name. `bin/build` ends with a fill step: it runs the new image with the
  folder writable and calls `playwright install`, `cypress install`, the
  model download, the Chrome download, `npm install` of the CLIs. Each is a
  no-op when its version is there. So a Playwright bump downloads 1 GB once;
  a week with no bump downloads nothing but Chrome and the CLIs.
- **Mounted `:O`, not `:ro`.** The lower folder is the host's, untouched;
  writes go to a throwaway layer that ends with the box. A project that
  pins another Playwright and runs `npx playwright install` keeps working
  as it does today, and cannot change what the other boxes run. Tested with
  the nested podman: a file written inside was visible inside and absent from
  the host folder; with `:ro` the same write failed.
- **No copy.** A bind mount is not part of the image, so the id-mapped copy
  shrinks to ~2.6 GB, and a host folder is stored once for all boxes.
- **The CLIs too.** Moving them out also means the image changes only once
  a week (the apt refresh), not daily: one ~2.6 GB copy a week instead of a
  ~6 GB copy a day. This is the CLI part of the earlier audit's design;
  `data/tools/` was created for it and is still empty.

What it costs and what to know:

- The image alone no longer runs a browser or an agent: a box started before
  the first fill has neither. `bin/run` should stop with "run bin/build"
  when `data/extras` is missing, and `bin/missings` report it.
- Chrome needs its libraries in the image. The image keeps the
  `google-chrome-stable` package's `Depends` (nearly all already there from
  `playwright install-deps`); only the files under `/opt/google/chrome` move,
  unpacked with `dpkg-deb -x`. A version folder plus a `current` link lets a
  running box keep its Chrome while the fill brings the next one; the fill
  keeps the last two.
- Old browser revisions: `playwright install` deletes revisions no installed
  Playwright refers to. Across image versions that rule sees the old image's
  Playwright as gone, which is what we want, but a box still running the old
  image would lose its browser mid-run. The fill should skip that clean-up
  while another box runs, or keep the previous revision until the next fill.
- The build's checks that need the browsers (`cypress verify`, Puppeteer
  resolving Chrome, the headless-shell screenshot) move into the fill step.
- Disk: the folder holds the same 3.5 GB, once. The saving is in the image,
  its copy, and the daily rewrite.

### BOX-02 Each daily build leaves the previous image and its 6 GB copy behind (high)

`bin/build:35–38` tags the new image `ai-box`; nothing removes the image it
replaces. The old one stays as `<none>`, with its id-mapped copy, which
shares nothing with the new one's copy. On this measure a week of daily
builds can hold ~40 GB of copies no box uses. The host's disk is at 100%
(5.6 GB free, `df` from the box).

Not verified on the host: the store is not visible from the box. On the host:

```
podman images -a
podman system df
```

If the `<none>` images are there, `bin/build` should remove the image it
replaced once the new one is warmed, unless a running box uses it
(`podman image rm` refuses an image in use, which is the right check).

### BOX-03 Chrome and Playwright's Chromium are two Chromiums (medium)

`Dockerfile:211` and `:413`. Google Chrome 154 (437 MiB) serves Puppeteer and
`google-chrome`; Playwright's Chromium 151 (390 MiB) serves Playwright.
Pointing Puppeteer at Playwright's Chromium removes 437 MiB, but Chromium has
no H.264/AAC, so an `.mp4` banner or video would not play in Puppeteer, and
`google-chrome` disappears. The other way round, Playwright on
`channel: 'chrome'`, removes 390 MiB, but every Playwright suite has to name
the channel, and projects with their own Playwright do not. Neither is
free; with BOX-01 both live outside the image anyway, so I'd keep both.

### BOX-04 The rest of the image is a floor, not waste (low)

After BOX-01 the image is ~2.6 GB: apt ~1.5 GB, Python 0.57 GB, Node 0.2 GB,
ImageMagick 0.1 GB, small npm libraries 0.17 GB. No cleanup with no loss
is worth doing: docs are 16 MiB, man pages and locales 3 MiB, Python bytecode
26 MiB. The next steps each remove a capability:

| Option | MiB | Loses |
|---|---:|---|
| Whisper's Python stack (CTranslate2, PyAV, onnxruntime) into the extras folder as a venv | ~310 | nothing, but `transcribe` needs the folder; more moving parts |
| gcc, g++, `php-dev`, Node headers | ~220 | building native npm/PECL modules in the box |
| GTK/GStreamer libraries | unmeasured | Firefox and WebKit, unless they move with their libraries |

## What is good

- One of each: one Chrome for Puppeteer, no apt ImageMagick, no second
  headless Chromium; rembg gone.
- Download caches (apt, npm, pip) are cache mounts, never in a layer.
- Every temporary download is removed in the layer that made it.
- The environment variables the extras folder needs are already the ones the
  image sets.

## Recommended order of work

1. BOX-02: check `podman images -a` on the host; if it shows old images,
   `bin/build` removes the one it replaced. Frees disk today.
2. BOX-01, the CLIs first: `data/extras/npm`, filled by `bin/build`. The image
   stops changing daily; ~0.67 GB out.
3. BOX-01, Playwright, Cypress and the model: ~2.4 GB out, `:O` mount,
   `bin/run` refusing to start without the folder.
4. BOX-01, Chrome: its dependencies stay, its files move; ~0.44 GB out.
5. BOX-04 only if 2.6 GB is still too much.
