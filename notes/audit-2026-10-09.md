# Project audit: ai-box against the rulebook

Audited 2026-10-09. Repository vbarbarosh/ai-box, branch main, HEAD
`819eeb6`, 50 tracked files (24 bash, 2 node, 1 python, the Dockerfile,
README, notes, images). Rulebook vbarbarosh/rules at `8a56f24`, 269 rules in
18 groups.

## Scope

Every rule of the index (`docs/rules.md`) was read against every tracked
file, in three passes: layout, packaging, commits, uniformity and writing
(PROJ, REL, GIT, CORE, DOC); names, variables, function contracts, control
flow and file structure (NAME, VAR, FN, FLOW, FILE), bash included; and
formatting, the linter and logs (FMT, LINT, LOG). Each finding was then
applied in the working tree, apart from the ones named below as left.

Checks run on the result: the lint workflow's five steps (`bash -n` and
shellcheck 0.10.0 `-S warning` over every bash script, hadolint 2.12.0,
`node --check` and the python compile, the executable bits); the rules preset
(`eslint.projects.config.js`) over `bin/usage` and `files/bin.ai/tts`, exit 0
(exit 1 with 20 errors before); `bin/usage`'s table rendered from fixed data
before and after, identical apart from winter times; `bin/configure` against a
stubbed sudo and dpkg (nothing to do, a missing package with and without a
ticket, a dry run, a short subuid range); `bin/build`'s last step against a
stubbed podman (all pass, fill fails, check fails, check fails on a first
build); `bin/run`'s options through a stubbed podman (old and new limit and
mask names, delegated controllers); the commit relay driven through its
socket against a scratch repository (two files committed, a masked `.env`
refused); `diskperf` beside a file named `tmpfile`; `bin/images --remove` of
an unknown image.

Not done: `bin/build` end to end and a box from its image. The box this
audit ran in has a subordinate range of 999 ids, too short for the Ubuntu
image, so the build, the warming, the fill and `bin/self-check --deep` were
not run for real. CSS, SQL, VUE, UI and UIM have nothing to reach: ai-box has
no stylesheet, query, component or page.

## Findings

### BOX-05 The build ships its image before any check (medium)

`bin/build:52-55` tagged the new image `ai-box` and nothing checked it
afterwards; a failed fill left an unfilled image as the one `bin/run` starts.
Now `bin/missings` is `bin/self-check` (the rule's name; references in
`bin/configure`, `bin/run`, the Dockerfile, the workflow and the docs follow),
the build ends with `bin/self-check --deep`, and a failed fill or check tags
the previous image `ai-box` again, or untags a first build. Old images are
removed only after the check passes. The fill keeps the previous image's
extras for KEEP_DAYS, so the restored image starts as before.

### BOX-06 `diskperf` overwrites and deletes `./tmpfile` (medium)

`files/bin/diskperf:15-16` wrote `tmpfile` in `$PWD` and removed it. It now
writes `mktemp -p $PWD .diskperf.XXXXXXXXXX`, removed by an EXIT trap; it stays
in `$PWD` so `df` and `dd` measure one disk. 09-06's P1, open until now.

### BOX-07 No script follows the rules' templ (medium)

`files/bin/templ` emitted a skeleton without the colours and the exit message,
so no script printed one. It now emits the rules' `bin/templ` verbatim.
`bin/build`, `bin/configure`, `bin/images`, `bin/self-check` and
`extras-fill` start with a red "failed" and end with a green "succeeded";
`bin/self-check`'s summary is that message. `bin/configure` calls the check
instead of `exec`, or its trap would never run. `files/bin/git` and
`files/bin.ai/google-chrome` got the prologue. Left without an exit message,
decided: `bin/run`, `commit`, `push`, `pull`, `git`, `google-chrome` and the
entrypoint pass a program's own output and status through, and the helpers
that print data (`now`, `diskusage`, `hwdata`, `g` and the rest) would put a
line into what is piped or pasted.

### BOX-08 Limit and mask variables carry the project prefix (medium)

`bin/run` read `AI_BOX_MASK`, `AI_BOX_PIDS`, `AI_BOX_MEMORY`, `AI_BOX_CPUS`;
the author's rule is bare words, like `REPOS` and `NOTES` beside them. They
are `MASK`, `PIDS`, `MEMORY`, `CPUS`, with the same defaults; an old name
still set stops `bin/run` with `error: AI_BOX_MEMORY is gone: use MEMORY`,
as `GIT=rw` does. `WHISPER_MODEL` and `PLAYWRIGHT_SHELL_VERSION` stay: they
are image ENV every project in the box sees.

### BOX-09 The README is the whole documentation (medium)

442 lines with no quick start, Documentation or License section, and a
heading in backticks. The README is now the cover, `# ai-box`, one sentence,
a three-line quick start, `## Documentation` and `## License`. Everything
else moved verbatim to `docs/README.md`, one link mended
(`../notes/extras.md`). The GitHub About text ("Ubuntu image full of tools
for working with AI Agents") is a repository setting: the rule wants the
README's sentence there too.

### BOX-10 `tts` hand-rolls the process contract (medium)

`files/bin.ai/tts:20-23` was `main().catch(err => {...})`, and `parse_args`
exited by itself. It is `cli(main)` with the same in-file `cli` as `bin/usage`
(the image has no node-helpers); usage errors are thrown, so they exit 1, not
2. `voices.forEach` is a `for...of`; `duration_sec` is `duration_from_mp3`.

### BOX-11 to BOX-17

Applied as the rules state them: `bin/usage` operators (216, 228, 302);
`out` for the returned credentials and `rmi_message` / `nested_line` for
command output; `time0` and `format_duration` in `bin/build`; `format_bytes`
and `free_bytes_of_store`; `is_delegated`; `rundir`; parentheses at
`bin/usage` 50, 53, 58, 146, 297, 308, 382, 387, 431-434, 441-442.

### BOX-18 `bin/configure` asks for sudo before it knows it needs it (low)

It took `sudo -v` whenever no ticket was cached, so a re-run with nothing to
do still asked, and a short subuid range stopped it after apt. It now works
out the missing packages, devices and ranges first, stops on a short range
before any change, asks for sudo only when a step needs it, and every later
call is `sudo -n`.

### BOX-19 to BOX-33

Applied in place, one file each: `first`/`last` for the subuid range and
`request`/`response` in `bin/usage`; `packages`, `packages_missing`,
`controllers_delegated`, `pull_flag`, `is_new_week`, `removal`;
`report_ok`, `report_missing`, `check_binary`, `change`, `stop_warming`,
`check_branch`, `usage_print`, `visible_length_of`,
`playwright_locations_from_dry_run`; `ref_from_image`, `weekly_window`;
`partition_error`; `format_usd`, a local `format_bytes` in
`bin/self-check`, `format_duration` in `transcribe`; `tempdir`, `first_arg`,
`disks_count`, `fields`, `store_opts`, `not_executable`, `number_format`,
`windows_sorted_by_seconds`; `arg`, `relative`, `interface`, `path`,
`masked_paths`, `additional_rate_limit`; loop bounds in `tts` and
`bin/usage`; `extras-fill`'s puppeteer check; `bin/usage`'s `format_*` run
moved together; `date_format`, template strings, joined lines and the
blank lines; four-space indentation in `hwdata`, `netdata`, `bin/build`'s
case and the Dockerfile's shared-store step.

Left, with the reason: `hwdata`'s two unit loops (BOX-24) print both decimal
and binary sizes, which one `format_bytes` would not; `bin/usage`'s GPT
fetch callback and window sort (BOX-27) would be lines of 128 and 139
characters as arrows.

### BOX-34 The 10-07 note dropped open rows of 09-06 (low)

Its status table carried three of 09-06's twelve rows; two dropped rows were
still open in the code (BOX-06, BOX-38). The status table below carries
every row.

### BOX-35 Commit titles (low)

38 of 50 titles have no scope, 19 have capitals, two are over 72, and `run:`
and `bin/run:` name one part. History stays; new titles are lowercase, one
scope per part (`run`, `build`, `configure`, `self-check`, `usage`,
`extras-fill`, `readme`, `notes`), 72 characters at most.

### BOX-36, BOX-37, BOX-38 Outside the rules

The workflow's `bash -n` and shellcheck globs now include `files/bin.ai/*`,
so `google-chrome` is checked. `bin/usage` formats times in
`Europe/Chisinau` with the zone's own offset (GMT+2 from 2026-10-25) instead
of a fixed +3. `bin/images --remove` uses `if`/`else`, so a failed `rmi` no
longer pulls.

## What is good

No rule was broken in a way that changes what the box does: the scripts run
in strict mode, state lives under `data/`, secrets are masked, the node
scripts already used CommonJS, byte-ordered requires, `main` first and
`out` where it is returned. LOG's 23 rules have nothing to reach: they
describe the event logs of services and jobs, and ai-box has none (the build
log is a transcript of the terminal).

## Recommended order of work

1. Run `bin/build` on the host: the one path not run here. A failed check
   now keeps the previous image.
2. Commit, and set the GitHub About text to the README's sentence.
3. Say whether the data helpers should print an exit message after all
   (BOX-07), if the answer differs from the one decided.
